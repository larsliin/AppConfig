# Config Copier Chrome Extension - Development Instructions

## Project Overview
A Chrome extension that detects `appConfig.json` configuration files on webpages and displays them in a popup window with a Copy button. The popup follows browser dark/light mode settings and has a green Copy button (#2ecc71) matching the logo.

## Quick Build & Test
```bash
npm run build:extension  # Build the extension to dist-extension/
```
Then load `dist-extension/` folder in `chrome://extensions/` (Developer mode).

## Features
- **Smart Detection**: Automatically finds appConfig.json on page load
- **Visual Display**: Shows config content in a readonly textarea
- **One-Click Copy**: Green Copy button copies to clipboard
- **OS Theme Sync**: Automatically follows system light/dark mode preference
- **Status Indicator**: Shows current state (Ready, Loading, Error, etc.)
- **Comprehensive Logging**: Detailed [CS], [BG], [Popup] console logs for debugging
- **CSP Compliant**: All code follows Chrome Extension Content Security Policy

## Content Security Policy (CSP) Compliance

This extension strictly follows Chrome's CSP restrictions:
- ❌ NO inline scripts in HTML
- ✅ All scripts in external files
- ✅ All styles can be inline (CSS is allowed)
- ✅ No eval() or dynamic code execution
- ✅ No unsafe-inline attributes

**Key files for CSP compliance:**
- `popup.html` - No inline scripts (only CSS styling)
- `public/popup-init.js` - External script for initialization
- `src/popup.js` - Vue app entry point (external)
- All other scripts are external and bundled by Vite

If you add logging or event handlers to popup.html, ALWAYS create a separate .js file instead of inline `<script>` tags.

## How It Works

### User Flow
1. User opens webpage with appConfig.json
2. Content script auto-detects file on page load
3. User clicks extension icon
4. Popup displays file content in textarea
5. User clicks "Copy" button
6. Content is copied to clipboard
7. Button shows "✅ Copied!" confirmation

### Component Communication
**Content Script (content.js)**
- Runs on all webpages
- Searches for appConfig.json on page load
- Notifies background script when found
- Responds to popup requests with file data

**Background Script (background.js)**
- Service worker managing state
- Receives "getConfig" messages from popup
- Routes to content script for file detection
- Caches config locally for performance
- Stores in Chrome storage for persistence

**Popup UI (Popup.vue)**
- Vue 3 component with reactive state
- Displays config content in monospace textarea
- Green Copy button for clipboard operation
- Real-time status indicator
- Auto-syncs with OS light/dark preference

## Theme System (useTheme Composable)

### Architecture
- **composables/useTheme.ts**: Vue 3 composable for automatic OS theme syncing
- **assets/main.css**: CSS variables for light/dark color schemes

### How It Works
1. **Automatic Sync**: Extension automatically detects OS theme preference on load
2. **Real-time Updates**: Listens to OS theme changes and updates instantly
3. **CSS Variables**: Theme applied via `data-theme` attribute on `<html>` element
4. **No Manual Selection**: No UI controls - always follows OS preference

### CSS Variable System
Light mode (`:root[data-theme='light']`):
- `--color-bg: #f3f4f6` (Light gray background)
- `--color-panel: #ffffff` (White panels)
- `--color-text: #1f2937` (Dark text)
- `--color-text-muted: #5b6472` (Medium gray)
- `--color-accent: #1D9E75` (Green)

Dark mode (`:root` default):
- `--color-bg: #1e1e1e` (Dark background)
- `--color-panel: #2b2b2b` (Darker panels)
- `--color-text: #e0e0e0` (Light text)
- `--color-text-muted: #9a9a9a` (Medium gray)
- `--color-accent: #1D9E75` (Green)

## File Search Locations
Content script searches in this order:
- `/appConfig.json` (root)
- `./appConfig.json` (current directory)
- `../appConfig.json` (parent directory)
- `appConfig.json` (relative)

## Chrome Permissions

- `scripting` - Run scripts on pages

## Known Limitations
- File must be valid JSON
- File must be at one of the configured paths
- File must return Content-Type: application/json
- Works only when content script is injected

## Bug Fixes & Known Issues

### Cross-Tab Contamination (FIXED)
**Issue**: The "Add localhost" toggle showed incorrect state when switching between tabs.

**Cause**: 
1. `background.js` had a `chrome.storage.local` fallback that persisted cached config across tabs
2. `Popup.vue` didn't comprehensively reset all state variables before fetching new data

**Solution**:
1. Removed storage fallback in `background.js` - content script is now authoritative, no stale cache
2. Added `resetAllState()` function in `Popup.vue` that resets all 10 reactive variables
3. `resetAllState()` is called at START of `loadConfig()`, before any async operations

**Expected Behavior**:
- If localhost NOT in original file → toggle OFF and EDITABLE
- If localhost IN original file → toggle ON and READ-ONLY  
- Each popup open fetches FRESH data from current tab
- NO cross-tab data leakage
- Toggling ON adds localhost to display only (non-persistent)

**Test**: Open popup in Tab A (with localhost) → switch to Tab B (without localhost) → open popup → toggle should show OFF/editable reflecting Tab B's actual config

## Do NOT
- ❌ Change manifest version below 3
- ❌ Use inline scripts in popup.html
- ❌ Add external CDN resources
- ❌ Remove [CS], [BG], [Popup] logging for debugging
- ❌ Generate separate documentation files (use this file)
- ❌ Use `chrome.storage.local` as fallback for content script data (causes cross-tab contamination)
- ❌ Partially reset Vue state in `loadConfig()` (always call `resetAllState()` first)
- ❌ Skip the `resetAllState()` call when adding new Vue reactive variables
- ❌ Use icons other than Bootstrap icons (unless specifically told to by user)

## Copilot Notes
When debugging or modifying:
1. Content script logs start with [CS]
2. Background logs start with [BG]
3. Popup logs start with [Popup]
4. Always trace all three components
5. Use `chrome.tabs.sendMessage()` with try/catch
6. Return `true` from message listeners for async responses
7. Dark mode: Use `light-dark()` CSS function or `prefers-color-scheme`
8. Test on both light and dark mode browsers
9. Green color for buttons: #2ecc71 (matches logo)
